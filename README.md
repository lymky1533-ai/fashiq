# مجمع الفاشق لخدمات السيارات

تطبيق ويب عربي RTL لإدارة المخزون والعمليات التشغيلية، مبني على React وTypeScript وExpress وtRPC وDrizzle، داخل مشروع WebDev المُدار القائم.

## قاعدة البيانات الدائمة

المشروع يستخدم قاعدة **MySQL مُدارة من WebDev**؛ ليست Supabase أو PostgreSQL. التطبيق يقرأ اتصال قاعدة البيانات من بيئة الخادم؛ لا تُحفظ بيانات الاتصال في الواجهة أو Git. الهجرات `0000` و`0001` محفوظة، وتضيف `0002` جداول المرحلة الثانية و`0003` حالة رصيد الصندوق، دون إسقاط الجداول أو حذف بيانات المرحلة الأولى.

تُحفظ الأرصدة والحركات بكميات ومبالغ `DECIMAL(18,6)`. فاتورة الشراء/البيع أو الصيانة، بنودها، تحديث المخزون، الدفعة النقدية وحركة التدقيق تُنفذ في معاملات مترابطة. دفتر الصندوق دائم، مع رصيد حالة يُقفل ويُحدّث داخل المعاملة لمنع صرف متزامن يتجاوز الرصيد. مفاتيح طلب فريدة وروابط مصدر فريدة تمنع تكرار الفواتير وحركات المخزون والصندوق. قاعدة التطوير مشتركة مع النسخة المنشورة؛ اختبر على بيانات آمنة فقط.

الاسم الافتراضي «مجمع الفاشق لخدمات السيارات» والعملة `YER` (الريال اليمني). تعديل الاسم/العملة عبر شاشة الإعدادات غير منفذ حاليًا.

## تهيئة المدير الأول

يُضبط `FASHIQ_INITIAL_ADMIN_TOKEN` من أسرار مشروع WebDev، ولا يوجد في ملفات المشروع. افتح شاشة التطبيق، اختر «إعداد حساب المدير الأول»، أدخل الرمز الذي حُفظ في إعدادات المشروع ثم أنشئ اسم مستخدم واسمًا ظاهرًا وكلمة مرور قوية (10 أحرف على الأقل). لا توجد حسابات افتراضية أو بيانات أعمال تجريبية. بعد إنشاء المدير الأول تُغلق التهيئة الأولى، ويستطيع المدير إنشاء حسابات الموظفين وإيقافها من التطبيق.

تُجزّأ كلمات المرور باستخدام scrypt مع ملح عشوائي، وتُحفظ رموز الجلسات مجزأة فقط. الجلسة في كوكي HttpOnly/Secure، وتُفرض الأدوار في إجراءات الخادم.

## الوظائف المنفذة في المشروع

- لوحة تحكم تقرأ ملخص المنتجات والمخزون والحركات، وتعرض المبيعات والمشتريات والذمم والصندوق والمصروفات وأوامر الصيانة بحسب الدور.
- منتجات وتصنيفات وتعبئات خاصة بكل منتج: قطعة أو لتر أو عبوة أو برميل. الاختيار والبحث باسم المنتج فقط؛ لا باركود أو رمز منتج ظاهر. إدخال وصرف وتسوية مع سجل مخزون.
- إدارة الموردين وفواتير شراء نقدية وآجلة، مدفوعات جزئية، أرصدة، مرتجعات وربط الحركة بالمخزون.
- إدارة العملاء وفواتير بيع نقدية وآجلة، تحصيلات وديون ومرتجعات؛ وفواتير يمكن طباعتها.
- تسجيل المركبات وربطها بالعملاء، أوامر صيانة بفني وخدمات وأجور وقطع/زيوت، حالات من الاستلام إلى التسليم، وفاتورة مجمعة للخدمات والمواد.
- مصروفات بفئات نصية مثل الإيجار والأجور والكهرباء وغيرها، حركات قبض وصرف ورصيد وسجل عمليات.

## التشغيل والتحقق

- `pnpm dev` يشغّل خادم التطوير على `PORT` أو المنفذ 3000.
- `pnpm check` فحص TypeScript.
- `pnpm test` اختبارات Vitest.
- `pnpm build` يبني الواجهة والخادم.
- `pnpm db:migrate` يطبق الهجرات.
- `pnpm exec drizzle-kit generate` يولّد هجرة جديدة؛ راجع SQL قبل تطبيقه على قاعدة المشروع المشتركة.

آخر تحقق مسجل: `pnpm check` نجح؛ `pnpm test` نجح بـ19 اختبارًا في 5 ملفات؛ `pnpm build` نجح مع تنبيهات غير مانعة من Vite حول سكربت إعداد المنصة وحجم حزمة JavaScript. `/api/health` و`/manus-routes.json` أعادا HTTP 200. طلبات الموردين وأرصدة الموردين والعملاء والسيارات والصندوق والتقارير دون جلسة أعادت HTTP 401، واختبارا الصلاحيات يرفضان دور المبيعات والفني قبل الوصول إلى قاعدة البيانات. جداول المرحلة الثانية موجودة.

**لم يُنشأ حساب مدير بعد، ولم تُنفذ فواتير أو حركات اختبار في قاعدة الأعمال المشتركة.** لذلك لم يتم التحقق end-to-end بحساب مصادق عليه من سيناريوهات الشراء/البيع/المرتجعات/الصيانة/المصروفات؛ لا توجد بيانات اختبار في قاعدة المشروع. يلزم أن يهيئ المالك حساب المدير ثم يختبر على سجلات حقيقية أو بيئة اختبار معزولة قبل الاعتماد التشغيلي الكامل.

المحاسبة المتكاملة والقيود والأرصدة الافتتاحية والقوائم المالية مؤجلة للمرحلة الثالثة بطلب مستقل.
